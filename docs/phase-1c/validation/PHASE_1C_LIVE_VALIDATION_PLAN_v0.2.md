# Phase 1C Live Validation Plan

> Дата: 2026-06-06
> Статус: План (ожидает выполнения)
> Цель: Проверить `task_cancel` на реальном кластере PVE 9.2.3

---

## 1. Prerequisites

- [ ] Кластер PVE 9.2.3 доступен
- [ ] Токен `ai-agent@pve!openwebui` сконфигурирован
- [ ] Проект собран (`pip install -e .` или `uv sync`)
- [ ] Есть запущенная задача для отмены (рекомендуется `vzdump` или длительная операция)

---

## 2. Тестовые сценарии

### TC-1: Endpoint Availability

**Цель:** Проверить, что POST endpoint `/nodes/{node}/tasks/{upid}/status/stop` доступен и отвечает 200.

**Метод:** Прямой HTTP-запрос через curl или httpx к PVE API.

```bash
curl -k -X POST \
  -H "Authorization: PVEAPIToken=ai-agent@pve!openwebui=<token>" \
  "https://<host>:8006/api2/json/nodes/<node>/tasks/<upid>/status/stop"
```

**Ожидание:** HTTP 200, `{"data": null}`

**Критерий:** Endpoint не возвращает 404, 501 или 500.

---

### TC-2: Required Permissions

**Цель:** Определить минимальные права, необходимые для остановки задачи.

**Метод:** Выполнить `task_cancel` с текущим токеном `ai-agent@pve!openwebui`.

**Ожидание:** Если `Sys.Modify` не назначен — ошибка 401/403 с указанием недостающих прав.

**Критерий:** Ошибка однозначно указывает на недостаток прав (не "endpoint not found").

---

### TC-3: wait=false

**Цель:** Проверить режим немедленного возврата.

**Метод:** Вызвать `task_cancel` для запущенной задачи с `wait=false`.

**Ожидание:** Ответ содержит `cancel_requested: true`, `stopped: false`. Ответ возвращается немедленно (без задержки).

---

### TC-4: wait=true (успешная остановка)

**Цель:** Проверить режим ожидания с успешной остановкой.

**Метод:** Вызвать `task_cancel` для запущенной задачи с `wait=true`.

**Ожидание:** Ответ содержит `cancel_requested: true`, `stopped: true`, `message: "Задача остановлена"`. Ответ возвращается после фактической остановки задачи.

---

### TC-5: wait=true (таймаут)

**Цель:** Проверить обработку таймаута при ожидании.

**Метод:** Вызвать `task_cancel` с `wait=true` и малым `timeout` (например, 1 сек) для задачи, которая не останавливается.

**Ожидание:** Ответ содержит `cancel_requested: true`, `stopped: false`, `message` с указанием таймаута.

**Примечание:** Сложно гарантировать, что задача не остановится за 1 сек. Возможно, потребуется специально созданная долгая задача.

---

### TC-6: Повторная отмена

**Цель:** Проверить поведение при повторном вызове `task_cancel` для одной задачи.

**Метод:**
1. Вызвать `task_cancel` для запущенной задачи (ожидается `cancel_requested: true`)
2. Вызвать `task_cancel` для той же задачи повторно (ожидается сообщение о завершении)

**Ожидание:** Второй вызов возвращает осмысленный ответ, не вызывает ошибку PVE API.

---

### TC-7: Отмена завершённой задачи

**Цель:** Проверить поведение при вызове `task_cancel` для уже завершённой задачи.

**Метод:**
1. Найти завершённую задачу (через `task_list` или `task_status`)
2. Вызвать `task_cancel` для неё

**Ожидание:** Ответ содержит `cancel_requested: false`, `message: "Задача уже завершена"`.

---

### TC-8: Обработка ошибок

**Цель:** Проверить обработку ошибочных ситуаций.

**Метод:**
1. Вызвать `task_cancel` с несуществующим UPID
2. Вызвать `task_cancel` с несуществующей нодой

**Ожидание:** В обоих случаях возвращается `PveApiError` с понятным сообщением.

---

## 3. Скрипт валидации

Рекомендуется создать Python-скрипт `scripts/validate_live_phase1c.py` по аналогии с `scripts/validate_live_phase1b2.py`.

Сценарии скрипта:
1. Получить список задач ноды
2. Найти запущенную задачу (или создать тестовую)
3. TC-3: wait=false
4. TC-4: wait=true (если задача ещё запущена или другая)
5. TC-6: повторная отмена
6. TC-7: отмена завершённой (найти в списке)
7. TC-8: несуществующий UPID

---

## 4. Критерии прохождения

- [ ] TC-1: Endpoint доступен (200 OK)
- [ ] TC-2: Права доступа задокументированы (успех или понятная ошибка)
- [ ] TC-3: wait=false — немедленный ответ
- [ ] TC-4: wait=true — успешная остановка (если применимо)
- [ ] TC-5: wait=true + таймаут (если возможно)
- [ ] TC-6: Повторная отмена — осмысленный ответ
- [ ] TC-7: Завершённая задача — cancel_requested: false
- [ ] TC-8: Ошибки — понятные сообщения

Минимальный проход: **TC-1 + TC-3 + TC-6 + TC-7 + TC-8** (4 из 8).
