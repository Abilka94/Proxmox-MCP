## C. Допуск специально созданной задачи

До любого создания задачи или DELETE требуется отдельное разрешение пользователя на конкретный сценарий. В разрешении фиксируются node, полный UPID (после создания), тип, владелец, назначение, ресурс и последствия остановки. Если UPID появился после разрешённого создания, оператор сверяет его перед DELETE с одобренным объектом.

Задача должна быть специально подготовлена оператором, принадлежать тестовому токену и не затрагивать production. Запрещены производственные задачи, резервное копирование, миграции и задачи других пользователей. Универсальная безопасная задача для произвольного кластера не предполагается: тип и способ создания остаются отдельным решением оператора. Нет создания task через SSH/sleep/kill как обхода API.

Перед DELETE повторно проверить node, владельца, цель и running; при любом расхождении остановить проверку. Не расширять ACL автоматически; если минимальные права недостаточны — зафиксировать отказ и запросить отдельное решение. Не выдавать root/Admin и не отключать privsep для прохождения теста.

## D. Разрешаемые отдельно live-сценарии

Все строки имеют статус **не выполнено**.

| ID | Проверка | Критерий |
|---|---|---|
| L1 | GET завершённой разрешённой тестовой задачи, затем task_cancel | cancel_requested=false, status=stopped, stopped=true; DELETE отсутствует |
| L2 | task_cancel wait=false на собственной running тестовой задаче | ровно DELETE, HTTP 200 data:null; cancel_requested=true, status=unknown, stopped=null |
| L3 | независимый READ после L2 | фактический status/log/exitstatus сохранён, причинность не заявляется |
| L4 | другая одобренная задача, wait=true | terminal наблюдён: stopped=true, exitstatus сохранён; либо корректный timeout/error |
| L5 | повторный вызов для одобренного UPID | stopped до вызова → DELETE отсутствует; если running — повторный DELETE только в пределах разрешённого сценария |
| L6 | гонка/естественное завершение | если наблюдается, фиксируется без заявления отмены; специально не провоцировать на production |

Отказы 401/403/404/501, сетевой unknown, malformed JSON, ошибка наблюдения, строгий timeout и повтор при running проверяются прежде всего локальным MockTransport. Live-инъекция сетевых сбоев, отзыв прав, вызовы на чужой задаче и намеренно неостанавливаемая задача не требуются и не разрешены этим планом. Неудавшийся DELETE не повторять автоматически. Для unknown остановить mutate и выполнить только разрешённую READ-диагностику.

wait=false означает отсутствие polling, а не мгновенность DELETE. Timeout наблюдения не доказывает, что задача продолжает работать. Terminal и exitstatus не доказывают, что задача отменена именно этим запросом. Отмена не является rollback; последствия проверяются отдельно по одобренному типу задачи.

## E. Фиксация и завершение

Для каждого шага: время, версии пакетов/кода, correlation id, node/UPID, владелец, разрешение, method/path без credentials, HTTP/status/envelope, MCP-поля, duration, независимый GET/log и последствия. Отчёт хранить в validation/; не вписывать ожидаемые результаты как фактические.

Минимум перед Acceptance: локальная матрица проходит; READ_ONLY/OPERATOR подтверждены; L1–L5 выполнены в разрешённых условиях (либо ограничения отдельно приняты), реальные ошибки не маскируются успехом, результаты задокументированы. PVE 8.x проверять только при доступной отдельной тестовой среде; отсутствие проверки обозначить best effort. Acceptance, commit/tag — отдельные этапы, сейчас не выполняются.
