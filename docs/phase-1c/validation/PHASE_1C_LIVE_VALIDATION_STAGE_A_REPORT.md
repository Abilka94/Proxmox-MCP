## READ-проверки соединения

Запросы ограничивались GET и host из local.yaml. В диагностическом HTTP-клиенте установлен request-hook, запрещающий любой иной метод или host; redirects отключены. HTTPS API запросы использовали существующий verify_ssl=false, без его сохранения/изменения. Отдельная TLS-проба использовала системную проверку сертификата.

Таймаут не является HTTP 401/403 и не доказывает неверность токена или отсутствие прав. Ошибка TLS не была ошибкой сертификата: до подтверждённой проверки доверия соединение не дошло.

Адрес совпадает с endpoint исторического Pre-Validation Report, но его принадлежность текущему целевому кластеру не доказана: свежих version/nodes нет. Исторические PVE 9.2.3/pve/pve2/pve3 и предоставленный ранее пользователем pvesh на 9.2.21/7700T не смешиваются и не объявляются обнаруженными сейчас. Другие IP/серверы не перебирались.

## Маршрут отмены без DELETE

Текущий код использует DELETE /api2/json/nodes/{node}/tasks/{upid}. Исторически пользователь предоставил pvesh usage с get/delete на PVE 9.2.21; это подтверждает регистрацию в той проверке. Upstream API и формат UPID ранее сверены в Design/Review.

Но **на адресе из local.yaml установленную схему сейчас подтвердить не удалось**: GET apidoc.js завершился ConnectTimeout. Успех локальных tests или READ не заменяет регистрацию в установленном пакете и не подтверждает выполнение DELETE. Ни пробный DELETE, ни OPTIONS/POST как обход не выполнялись.

## Безопасный сценарий и блокирующие условия

**Подтверждённого безопасного сценария создания task пока нет.** Выбирать ноду без актуального inventory нельзя; 7700T — только исторический кандидат из пользовательской проверки, не выбранная/подтверждённая цель. Существующие задачи не выбирались для отмены.

Требования к будущему сценарию: отдельная изолированная lab-нода или явно выделенный тестовый контур, специально созданная собственная token-owned задача, известные тип/назначение/ресурс/эффект прерывания и наблюдаемая достаточная длительность. UPID получить из ответа отдельно разрешённого API-вызова создания задачи, затем сверить node/type/owner/status через GET. Предпочтителен подтверждённый штатной установленной схемой worker без полезной нагрузки на VM/LXC/storage; наличие такого generic test/no-op endpoint не доказано. Выдуманный endpoint создания task не предлагается.

Console/shell task не предлагается как готовая замена: console endpoints имеют token-ограничения; SSH/kill запрещены. Backup/migration, произвольная production задача, создание/остановка VM/LXC и запись в рабочее хранилище не подходят. Если штатного безопасного worker нет, оператор должен отдельно определить и одобрить изолированный тестовый сценарий; до этого создание задачи и этап B блокированы. Это ограничение нельзя исправить одним расширением ACL.

Немедленно прекратить будущую проверку при несовпадении endpoint/node/owner/UPID, неясных последствиях, production ресурсе, смене прав, ошибке preflight/схемы, неизвестном исходе DELETE или нарушении TLS-условий. Не выполнять автоматический повтор mutate.

## План этапа B — только после отдельного разрешения

1. **Разблокировать цель READ-диагностики:** пользователь подтверждает актуальные endpoint/кластер и доступ Windows (маршрут/VPN/firewall). Если local.yaml устарел, изменение файла требует отдельного разрешения и повторной READ-проверки. Не пробовать другие сервера наугад.
2. Получить GET version/nodes/permissions/task status/log и установленную API-схему. Зафиксировать версии пакетов/схемы, node/owner и наличие DELETE без вызова. При любом непроходе остановиться.
3. Установить TLS-политику: текущий verify_ssl=false не подтверждает подлинность сервера. Предпочтителен доверенный сертификат/CA; его настройка или принятие текущего режима требуют отдельного решения, не выполняются в A.
4. Подтвердить подключение нужного MCP к Codex, явный путь local config и интерпретатор/checkout. Без активного connector нельзя объявить end-to-end Windows → Codex → MCP проверенным.
5. Определить изолированный task/type/способ создания/эффекты. Получить отдельное разрешение на создание и на конкретные отмены с wait=false/wait=true. Если безопасный тип не определён — B не начинать.
6. Проверить минимальные права: начать с собственной token-owned задачи; чужие задачи исключить. Только при доказанном недостатке отдельно согласовать минимальный scope/срок ACL и возврат; отсутствие прав на создание не считать автоматически недостатком прав DELETE.
7. Отдельно разрешить временный OPERATOR и перезапуск нужного MCP; сохранить исходный READ_ONLY и план восстановления. Не менять tier task_cancel.
8. Создать только разрешённую тестовую задачу через утверждённый API-сценарий; записать UPID из ответа; проверить GET node/type/owner/running перед DELETE. Не подменять её существующей production задачей.
9. Выполнить один разрешённый task_cancel wait=false, независимо прочитать status/log/exitstatus. На другой отдельно разрешённой задаче проверить wait=true. Повторный вызов разрешать в рамках сценария: если task ещё running, это ещё один DELETE.
10. Зафиксировать JSON pve_delete и domain events с correlation id, method/path, HTTP/envelope и фактическими последствиями без credentials. Terminal не объявлять доказанной причинностью отмены.
11. При error/unknown не повторять DELETE, сохранить cancel_requested и разрешённую READ-диагностику. Проверку ACL/сетевых отказов преимущественно оставить MockTransport; не отзывать права и не ломать сеть на кластере ради теста.
12. Восстановить согласованные временные режим/ACL, проверить READ_ONLY deny; завершить/убрать тестовый ресурс только если его cleanup отдельно разрешён. Написать фактический Live Validation Stage B Report, не переписывать ожидаемые результаты как выполненные.

Успех B: доказаны правильная цель/TLS/identity/installed route, строго разрешённые DELETE, корректные responses и наблюдение, отсутствие воздействия на рабочие сервисы, восстановление временных настроек и отчёт. Acceptance/commit требуют отдельных этапов.

## Итоговый вердикт и дальнейшие разрешения

**BLOCKED для B:** нет соединения с настроенным API, не подтверждены текущий кластер/версия/ноды/ACL/схема; отсутствует подтверждённый безопасный test task и активная подключённая MCP-цепочка. Локальная реализация/политики подготовлены, но не компенсируют эти блокеры.

Сейчас требуется подтверждение актуального адреса и доступности сети Windows, затем повтор только READ-части A. Создание задачи, DELETE, OPERATOR, конфигурация/TLS и ACL — лишь отдельными явно разрешёнными действиями после разблокировки. Этап A завершён; этап B не начат.
