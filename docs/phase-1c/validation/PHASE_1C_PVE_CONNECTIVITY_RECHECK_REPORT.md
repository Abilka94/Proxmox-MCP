## Авторизация и эффективные разрешения

Новый токен принят сервером для проверенных READ endpoints: HTTP 200 на permissions, node/task status/log подтверждает READ-доступ. Секрет не раскрывался.

| Путь | HTTP | Sys.Audit | Sys.Modify |
|---|---|---|---|
| /nodes/5800H | 200 | есть | нет |
| /nodes/CeleronG3930 | 200 | есть | нет |
| /nodes/7500T | 200 | есть | нет |
| /nodes/7700T | 200 | есть | нет |

В полученных grants присутствуют Datastore.Audit, Mapping.Audit, Pool.Audit, SDN.Audit, Sys.Audit, VM.Audit, VM.GuestAgent.Audit. Эффективные права сначала получены общей выборкой, затем отдельно по каждому node path.

Sys.Modify не подтверждён, а фактически отсутствует в возвращённых node grants. Это не препятствует выполненным READ-проверкам. Для будущей остановки чужой задачи это препятствие; возможность остановить собственную token-owned задачу определяется ownership-проверкой API и не требует автоматически Sys.Modify для любого случая. В этой диагностике DELETE/ownership будущей тестовой задачи не проверялись. Привилегии не расширялись, новый токен не создавался. Раздельные ACL пользователя/токена и privsep здесь не исследовались: получен именно итоговый effective permissions результат.

## TLS и блокирующие условия

При отдельной TLS-пробе с системной проверкой доверия получен **SSLCertVerificationError**. В отличие от прежнего адреса это не timeout: сервер доступен, но проверка сертификата не проходит. Точная причина (цепочка доверия, имя/IP или иное свойство сертификата) не устанавливалась и не выдумывается.

Успешные HTTP 200 получены с существующим verify_ssl=false. Таким образом, HTTPS-соединение работает, но криптографическая проверка подлинности сервера не подтверждена. Настройки не менялись. Перед будущими чувствительными действиями необходимо отдельно определить доверенную TLS-конфигурацию либо явно согласовать использование текущей; в рамках этой задачи таких действий нет.

Сетевой блокер прежнего endpoint снят для адреса 192.168.0.178. Блокеров для READ-диагностики при текущих настройках не обнаружено. Однако это не означает готовность к B: остаются отдельное разрешение, безопасная специально созданная test task, подтверждение её ownership/последствий, явный OPERATOR и решение TLS. Отсутствие Sys.Modify также не позволяет рассчитывать на отмену чужих задач. Регистрация/успешность DELETE на установленной системе в этой диагностике не проверялась.
