# Phase 1C — проверка прав Administrator и VM 301

> Дата: 2026-11-09 (Europe/Moscow)
> Режим проверки: только GET
> Результат: полномочия подтверждены; VM 301 существует, но находится в stopped

## Основание и границы

По поручению пользователя проверены текущие права ai-agent@pve!openwebui после изменения ACL, доступность VM 301 и сохранение READ_ONLY. Прочитаны README, индекс документации и PROJECT_WORKFLOW_RULES.md. По структуре фазы фактический отчёт помещён в validation/.

Использованы существующие load_config, auth_config_from_app_config и PveClient с config/local.yaml. Клиент HTTP внедрён штатным параметром, закрыт после запросов; диагностический guard разрешал только GET к 192.168.0.178. В первичном клиенте redirects отключены. Это диагностика API существующим PveClient, не выполнение task_cancel через MCP.

Никаких POST/PUT/PATCH/DELETE, qmshutdown, task_cancel, изменения VM, ACL, конфигурации, PolicyMode или исходников не выполнялось. На CeleronG3930/7700T и 5800H нодальные запросы не отправлялись. Общий GET ACL не меняет состояние нод. Секрет токена, Authorization header, посторонние ACL и чувствительное содержимое VM-конфига не выводились и не сохранялись. Commit/push/tag и этап B не выполнялись.

## ACL и эффективные полномочия

Отдельным GET /access/acl подтверждены только релевантные записи; прочие ACL в отчёт не включены:

| Субъект | Тип записи | Путь | Роль | propagate |
|---|---|---|---|---|
| ai-agent@pve | user | / | Administrator | 1 |
| ai-agent@pve!openwebui | token | / | Administrator | 1 |

Метаданные token подтверждают **privsep=1**. Таким образом, указанное пользователем разделение привилегий включено, а обе стороны получили распространяемое назначение. Фактический GET effective permissions дополнительно подтверждает доступ, поэтому вывод основан не только на имени роли.

| Привилегия | На / | На /vms/301 |
|---|---|---|
| VM.PowerMgmt | есть | **есть** |
| VM.Audit | есть | есть |
| VM.Allocate | есть | есть |
| VM.Config.Options | есть | есть |
| VM.Config.CPU | есть | есть |
| VM.Config.Memory | есть | есть |
| VM.Config.Disk | есть | есть |
| VM.Config.Network | есть | есть |
| Sys.Modify | есть | есть в возвращённых grants |
| Sys.Console | есть | есть в возвращённых grants |
| Permissions.Modify | есть | есть в возвращённых grants |

В /access/permissions перечислены также пути /access, /access/groups, /nodes, /pool, /sdn, /storage, /vms; широкие root grants включают Datastore, Mapping, SDN, GuestAgent и другие административные возможности. Наличие этих привилегий не является разрешением пользователя на их применение. Права на API и локальная MCP-политика независимы: **READ_ONLY продолжает запрещать OPERATOR tools**, даже если токен имеет Administrator. Рабочий режим не переключался, попыток mutate-проверки прав не было.

По сравнению с [прежней READ-диагностикой](PHASE_1C_PVE_CONNECTIVITY_RECHECK_REPORT.md) новые ACL фактически устранили наблюдавшееся отсутствие расширенных привилегий и прежний HTTP403 на чтение token metadata. Старый отчёт остаётся историческим снимком прежнего состояния.

Причина и момент остановки не исследовались; нельзя приписывать её task_cancel, пользователю, таймауту или иной операции без данных. VM не запускалась и не изменялась для приведения к ожидаемому состоянию.

В выборочной сводке config значения onboot/template/lock/agent/acpi не получены (null). Это не интерпретируется как явное значение 0: параметр может отсутствовать и иметь default. Полная проверка безопасности fixture (диски, сеть, HA, hookscript, прочие параметры) не входит в это задание и не объявляется выполненной. В частности, само имя тестовой VM не доказывает её изоляцию.

## Вывод и ограничения

- Соединение и авторизация: **PASS**, PVE 9.2.21, все 7 GET — HTTP200.
- Administrator user/token на / с распространением: **подтверждено GET ACL**.
- Privilege separation: **включено**, privsep=1.
- VM.PowerMgmt на /vms/301: **подтверждено effective permissions**.
- VM 301: **доступна на 7500T, stopped**, а не running.
- PolicyMode: **READ_ONLY**, без изменений.

Блокирующего недостатка VM.PowerMgmt больше не наблюдается. Но текущая stopped VM не подходит для немедленного создания running qmshutdown по ранее предложенному сценарию. Её запуск, изменение режима и любой тест отмены требуют отдельного разрешения; они не выполняются автоматически после проверки прав. Ограничение TLS сохраняется. Этап B не начат; готовность всей fixture и успешность DELETE этим отчётом не подтверждаются.

Созданы только этот отчёт и навигационные ссылки. Существующие незакоммиченные изменения сохранены. После проверки работа остановлена.
