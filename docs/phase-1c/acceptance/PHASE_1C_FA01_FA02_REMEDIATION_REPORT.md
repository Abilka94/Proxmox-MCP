## 1. Основание и исходные проблемы

Основание: явное разрешение пользователя удалить три файла после статической проверки зависимостей. Прочитаны [workflow](../../architecture/PROJECT_WORKFLOW_RULES.md), README, docs/README, [Final Acceptance Report](PHASE_1C_FINAL_ACCEPTANCE_REPORT.md) и относящаяся к Phase 1C документация. Исторический Final Acceptance Report сохранён без изменения содержимого; новый документ фиксирует последующее устранение FA-01/FA-02.

FA-01: в трёх untracked Python-файлах находился одинаковый непустой исторический секрет API-токена. Он отличался от текущего секрета рабочего конфига. FA-02: эти файлы могли при запуске/импорте отправлять прямые изменяющие API-запросы без MCP PolicyEngine и без актуальных ограничений теста. Их нельзя было включать в безопасный Git-пакет.

На старте HEAD `4561204`, последний тег `v0.3.0-phase1b.2`; Git status: **13 modified tracked + 29 untracked файлов**, индекс без staged-изменений. Все три цели существовали как обычные файлы в `docs/phase-1c/validation/`, не являлись symlink и не отслеживались Git. Поэтому удаление не создаёт строки `D` в tracked diff: файлы исчезают из untracked-кандидатов.

Скрипты не запускались и не импортировались. Для установления известного исторического секрета применён только AST-разбор текста; значение использовано в памяти при проверке совпадений. Значения секретов, Authorization headers и содержимое удалённых файлов не печатались, не включались в этот отчёт и не копировались в резервные файлы.

## 8. Остаточные риски и пределы

Удаление исправляет состав текущего рабочего дерева и будущего Git-пакета, но не отзывает credential и не удаляет возможные копии за пределами репозитория. Ранее раскрытый секрет нельзя считать безопасным только потому, что он перестал встречаться в рабочих файлах.

Три дополнительных потенциальных credential literals в старой tracked-документации требуют отдельного решения; здесь не производится очистка принятой исторической документации или Git history. Широкий секретный аудит всех возможных форматов и внешних копий не заявляется.

Настоящий отчёт не меняет общий REJECTED исторической приёмки. FA-03/FA-04 не исследовались дополнительно, не исправлялись и не принимаются автоматически; переход к ним не выполнялся. Рабочий TLS/ACL и прочий технический долг остались вне scope.
